베스킨라빈스 키오스크 주문 시나리오

원래모드와 쉬운모드의 주문 흐름 비교 화면

원래모드

여러 개의 메뉴를 먼저 선택한 뒤 주문 내역을 한 번에 확인하는 방식

1 광고화면
광고가 슬라이드 형태로 표시된다. 사용자가 화면을 터치하면 다음 단계로 이동한다.
↓
2 주문방법 선택
매장 식사 또는 픽업 방식을 선택한다.
↓
3 메인화면에서 메뉴 선택
3개를 주문하는 경우, 원하는 메뉴를 메인화면에서 총 3번 클릭한다.
예시 흐름
메뉴 1 선택 → 메뉴 2 선택 → 메뉴 3 선택
↓
4 컵 / 콘 / 와플콘 선택
예를 들어 싱글레귤러를 선택했다면 제공 방식을 선택한다.
컵 콘 와플콘
↓
5 맛 선택
선택한 메뉴에 들어갈 아이스크림 맛을 고른다.
↓
6 주문 내역 한 번에 확인
선택한 3개의 메뉴를 한 화면에서 한 번에 확인한다.
↓
7 할인 / 적립 페이지
쿠폰, 포인트 사용, 포인트 적립 여부를 선택한다.
↓
8 결제 페이지
QR 결제 또는 선택한 결제 방식으로 결제를 진행한다.
↓
9 영수증 선택
영수증 출력 또는 미출력을 선택한다.
출력 미출력
↓
10 주문번호 출력
결제가 완료되면 주문번호가 화면에 표시된다.

쉬운모드

하나의 메뉴를 끝까지 선택한 뒤 다시 메인으로 돌아오는 방식

1 광고화면
광고가 표시된다. 사용자가 화면을 터치하면 주문 화면으로 이동한다.
↓
2 주문방법 선택
매장 식사 또는 픽업 방식을 선택한다.
↓
3 쉬운모드 클릭
메인화면 좌측 상단의 언어 선택 버튼 옆에 있는 쉬운모드 버튼을 누른다.
UI 변화: 글자 크기 확대 / 버튼 크기 확대 / 화면 구성 단순화
↓
4 쉬운모드 메인화면
메뉴 화면이 2x2 구조로 바뀌어 더 크게 표시된다.
메뉴 1 메뉴 2 메뉴 3 메뉴 4
↓
5 메뉴 1개 선택
사용자는 한 번에 하나의 메뉴만 선택한다.
↓
6 컵 / 콘 / 와플콘 선택
싱글레귤러처럼 제공 방식이 필요한 메뉴라면 컵, 콘, 와플콘 중 하나를 선택한다.
컵 콘 와플콘
↓
7 맛 선택
맛 선택 화면은 3x3 구조로 바뀌어 크게 표시된다.
맛 1 맛 2 맛 3 맛 4 맛 5 맛 6 맛 7 맛 8 맛 9
↓
8 메인화면으로 돌아가기
하나의 메뉴 선택이 끝나면 다음 메뉴를 고르기 위해 다시 메인화면으로 돌아간다.
3개 주문 예시
메뉴 1 선택 완료 → 메인으로 이동
메뉴 2 선택 완료 → 메인으로 이동
메뉴 3 선택 완료 → 주문 진행
↓
9 할인 / 적립 페이지
모든 메뉴 선택이 끝난 후 쿠폰, 포인트 사용, 포인트 적립 여부를 선택한다.
↓
10 결제 페이지
QR 결제 또는 선택한 결제 방식으로 결제를 진행한다.
↓
11 영수증 선택
영수증 출력 또는 미출력을 선택한다.
출력 미출력
↓
12 주문번호 출력
결제가 완료되면 주문번호가 화면에 크게 표시된다.

원래모드는 여러 메뉴를 먼저 담고 한 번에 확인하는 흐름이고, 쉬운모드는 메뉴를 하나씩 완료하며 진행하는 흐름이다.

지점 ↔ 본점 시나리오 1 · 재고

📦 지점 ↔ 본점 시나리오: 재고 긴급 발주 및 자동화 프로세스

주말 프로모션을 앞두고 인기 메뉴 재고가 소진될 위기에 처한 지점의 긴급 발주 흐름

🏪 지점 측 흐름

BR-001 · BR-003 · BR-004 · BR-024 기반
현장 발주 신청 → 수령 확인 → 재고 자동 반영

⚙️ 키오스크 자동
1 안전재고 미달 — 자동 경고 발생
특정 인기 아이스크림 재고가 안전재고 기준 이하로 내려가면 시스템이 자동으로 경고 알림을 발생시킨다.
재고가 0이 되면 키오스크 화면에서 해당 메뉴를 즉시 자동 숨김 처리한다. (BR-024)
↓
🏪 지점 관리자
2 재고 현황 확인
지점 어드민에서 부족 재고 현황을 카테고리별로 확인한다. 재고가 적은 순으로 기본 정렬되어 우선순위를 쉽게 파악할 수 있다. (BR-004 · BR-025)
카테고리별 분할 부족 상품 강조 검색 기능
↓
🏪 지점 관리자
3 긴급 발주 신청
부족 상품을 선택하고 신청 수량과 사유를 입력하여 본점에 발주를 신청한다. (BR-001)
예시 사유 입력
"주말 '사이즈업' 이벤트 대비 사전 물량 확보 필요"
수량 입력 사유 필수 입력 신청 완료
↓
🏪 지점 관리자
4 발주 결과 확인
내 신청 내역 페이지에서 상태를 실시간으로 확인한다. 반려 시에는 반려 사유가 함께 노출되며, 재신청이 가능하다. (BR-002)
대기중 승인 배송중 반려
↓
🏪 지점 관리자
5 물품 도착 확인
배송된 물품이 실제로 도착하면 박스를 확인 후, 어드민에서 배송 진행 상황을 조회한다. (BR-003 · BR-009)
↓
🏪 지점 관리자
6 '수령 확인(배송 완료)' 버튼 클릭
시스템에서 수령 확인 버튼을 클릭하는 즉시 두 가지가 자동으로 처리된다. (BR-010)
① 지점 실재고 수량 자동 증가
② 품절 처리되었던 키오스크 메뉴 자동 복구 (판매 재개)

🏢 본점 측 흐름

HQ-001 · HQ-002 · HQ-003 · HQ-013 기반
발주 심사 → 승인/반려 → 배송 상태 관리

🏢 본점 관리자
1 전체 분점 발주 신청 목록 수신
모든 분점에서 올린 발주 신청이 본점 어드민 대시보드에 집계된다. 상태별·분점명·신청번호로 검색·필터가 가능하다. (HQ-001)
신청번호 분점명 상품·수량 신청일·상태
↓
🏢 본점 관리자
2 발주 상세 확인 및 심사
신청 상세 페이지에서 신청 사유·신청자·재고 여력을 종합적으로 검토하여 승인 또는 반려를 결정한다.
✔ 승인 처리
HQ-002: 대기중 → 배송 준비 상태 즉시 전환
✘ 반려 처리
HQ-003: 반려 사유 필수 입력 (예: 본점 창고 일시 품절)
↓
🏢 본점 관리자
3 배송 상태 단계별 관리
승인 후 물류가 출발하면 본점이 배송 상태를 직접 업데이트한다. 운송장번호·배송담당자·예상 도착일을 입력한다. (HQ-013)
접수 상품 준비 배송 중
↓
🏢 본점 관리자
4 배송 지연 건 모니터링
예상 도착일이 지났는데 지점에서 수령 확인이 완료되지 않은 건을 별도 목록으로 파악하고 후속 조치를 취한다. (HQ-015)
↓
🏢 본점 관리자
5 배송 완료 자동 확인
배송 완료 처리 권한은 지점에 있다. 지점이 '수령 확인'을 클릭하는 순간 본점 어드민에도 배송 완료 상태가 자동 반영된다.
배송 완료 시 본점 통합 재고 변동 이력 자동 기록 (감사 로그 S-094)
↓
🏢 본점 관리자
6 재고 조정 (예외 처리)
지점 실사 결과 수량 불일치가 발생한 경우, 본점이 증빙을 바탕으로 재고를 최종 수동 조정한다. 조정 사유 입력이 필수다. (HQ-006)

지점이 안전재고 미달을 인지하고 발주를 신청하면, 본점이 심사·배송을 진행하며, 지점이 수령 확인 시 재고와 키오스크가 자동으로 동기화된다.

지점 ↔ 본점 시나리오 2 · 이벤트

🎉 지점 ↔ 본점 시나리오: 이벤트 기획 및 적용 프로세스

본점이 전국 단위 이벤트를 하달하고, 지점이 로컬 상권 맞춤형 이벤트를 역제안하는 양방향 프로모션 흐름

📣 Top-Down: 본점 주도 이벤트

HQ-026 · HQ-027 · HQ-028 · HQ-029 기반
중앙 기획 → 전국 배포 → 지점 커스텀 적용

🏢 본점 관리자
1 이달의 맛 할인 이벤트 기획
본점이 '이달의 맛'을 지정하고 할인율을 설정한다. 500원 추가 결제 시 한 단계 큰 사이즈로 업그레이드되는 로직도 함께 적용한다. (HQ-026)
사이즈업 예시
싱글 레귤러 → 더블 주니어
싱글 킹 → 더블 레귤러
↓
🏢 본점 관리자
2 사이즈업 / 금액 할인 이벤트 배포
사이즈업 이벤트(HQ-027)와 n원 금액 할인 이벤트(HQ-028)를 전 지점에 일괄 배포한다. 금액 할인 이벤트는 적용할 '맛'을 지점이 직접 선택하도록 권한을 위임한다.
사이즈업 이벤트 이달의 맛 할인 n원 금액 할인
↓
🏢 본점 관리자
3 쿠폰 발송 (CRM 푸시)
DB에 등록된 고객 전화번호로 Firebase를 통해 n원 할인 QR코드 쿠폰을 일괄 발송한다. (HQ-029)
Firebase → 고객 휴대폰으로 할인 QR 쿠폰 전송
↓
🏪 지점 관리자
4 적용 '맛' 선택 (로컬 커스텀)
지점은 본점이 배포한 금액 할인 이벤트 틀 안에서 자기 매장 재고 상황에 맞게 구체적인 적용 맛을 직접 선택한다. (BR-029)
예시
본점 이벤트: "n원 할인 이벤트 배포"
지점 선택: 재고가 많은 초코칩 / 딸기 / 바닐라 중 선택
↓
⚙️ 키오스크 자동 적용
5 키오스크 이벤트 즉시 동기화
지점이 맛 선택을 완료하는 즉시 해당 지점 키오스크 DB와 동기화된다. 고객 주문 시 이벤트 팝업이 노출되며 결제 화면에 할인 로직이 자동 반영된다.
메인 배너 노출 결제 시 자동 할인 사이즈업 팝업

💡 Bottom-Up: 지점 주도 이벤트

BR-029 · HQ-028 기반
지점 역제안 → 본점 심사 → 승인 후 즉시 적용

🏪 지점 관리자
1 로컬 이벤트 기획 및 신청
지점장이 상권 특성과 재고 현황을 분석하여, 특정 메뉴 n원 할인 또는 로컬 사이즈업 이벤트를 본점에 신청한다. 신청 시 이벤트 사유를 반드시 기재한다.
신청 예시
"주말 상권 특성상 초코 계열 맛이 잘 팔림.
재고 소진 촉진을 위해 초코칩 맛 300원 할인 신청"
↓
🏢 본점 관리자
2 마진율 및 타당성 심사
본점이 지점의 이벤트 신청을 검토한다. 마진 구조, 타당성, 전체 브랜드 정합성을 기준으로 최종 승인 또는 반려를 결정한다.
✔ 승인
이벤트 최종 승인 → 지점 키오스크 즉시 활성화
✘ 반려
반려 사유 통보 → 지점 재신청 또는 내용 수정
↓
🏪 지점 관리자
3 지점 전용 이벤트 키오스크 활성화
승인된 즉시 해당 지점 키오스크에서만 지점 전용 이벤트가 활성화된다. 다른 지점에는 영향을 주지 않는다.
승인 즉시 해당 지점 키오스크 DB 자동 동기화
↓
⚙️ 키오스크 자동 적용
4 고객 주문 시 이벤트 자동 반영
고객이 키오스크에서 주문할 때 이벤트 대상 상품에 대해 할인 팝업이 자동으로 노출되며, 결제 화면에서 할인 금액이 즉시 차감 적용된다.
이벤트 팝업 노출 할인 자동 차감 결제 완료
↓
🏢 본점 관리자
5 이벤트 결과 통합 통계 확인
이벤트 종료 후 본점 통합 통계 대시보드에서 해당 이벤트가 적용된 지점의 매출 변화, 할인 적용 건수, 결제수단 비중 등을 확인한다. (HQ-008 ~ HQ-012)
매출 변화 할인 적용 건수 엑셀 다운로드

본점 주도 이벤트는 전국 단위 기획을 배포하고 지점이 로컬 맞춤 설정을 추가하는 방식이며,
지점 주도 이벤트는 지점이 상권 특성을 분석해 역제안하고 본점이 심사·승인하는 양방향 구조다.
